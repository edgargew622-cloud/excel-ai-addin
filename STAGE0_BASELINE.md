# Исходная версия для этапа 0

Дата проверки: 15 сентября 2026 года.

Последний коммит на момент начала этапа: `afe24fd` («Найдена причина: Excel держал кэш старого манифеста»). До моей реализации этапа 0 в индексе Git уже находились изменения 31 файла: 92 добавленные строки и 2574 удалённые строки относительно этого коммита. Среди удалённых файлов — модули бюджетов, метрик, проверки возможностей Excel, сохранения бесед, отдельный dev-манифест и скрипты запуска. Их назначение не подтверждено как согласованное к удалению. Эти подготовленные изменения сохранены; этап 0 не восстанавливает и не отменяет их автоматически.

Рабочая база на начало этапа:

- `npm test`: 9 тестов прошли.
- `npm --prefix server test`: 2 теста прошли, включая сборку сервера.
- `npm run build`: проверка типов и сборка панели прошли при запуске вне ограничений файловой песочницы. Внутри песочницы Vite/esbuild не мог прочитать родительский каталог; это ограничение среды проверки, а не ошибка TypeScript.
- Надстройка была ранее загружена в Excel после запуска локальных серверов и восстановления регистрации каталога. Полный цикл обращения к модели и запись в реальную книгу этим фактом не подтверждены.

На текущем этапе рабочая панель и API всё ещё запускаются двумя процессами на портах 3000 и 3001. Стабильный фоновый запуск, отдельная dev-панель и проверка после нового входа Windows относятся к этапу 1.

После изменений этапа 0 проверять одной командой `npm run check`. Команда объединяет тесты панели, серверные тесты и сборку. `npm run validate` остаётся отдельной проверкой манифеста, поскольку она может зависеть от внешних ресурсов.

Результат реализации этапа 0: `npm run check` прошёл — 13 тестов панели/агента, 2 серверных теста, проверка типов и production-сборка. `npm run validate` отдельно прошёл через сервис Microsoft. Обе команды для сборки/валидации пришлось запускать вне ограничений файловой и сетевой песочницы; это не требовало изменений конфигурации проекта.

Защита от повторной записи и лимиты проверены автоматическими тестами. Дополнительно выполнен реальный сценарий в Excel с отдельной книгой `stage0-formula-smoke.xlsx`: установленная локаль LCID 1049, агент прочитал пустую `Проверка!B2`, предложил `set_range_values` с `isFormula=true` и `=SUM(1,2)`, после подтверждения записал её и перечитал результат. Excel показал `Formula =SUM(1,2)`, `FormulaLocal =СУММ(1;2)`, `Value2 = 3`; агент сообщил `executionState: verified` и значение 3. Книга сохранена в корне проекта для повторной проверки. Другие открытые книги не изменялись.

Тест подтверждает путь записи формулы в русскоязычном Excel. Он не доказывает поведение на всех формулах, локалях и версиях Office. Отдельные испытания конфликтов и больших книг предусмотрены последующими этапами.

Для возврата к предшествующей сборке сначала нужно сохранить текущее состояние индекса и рабочих файлов и выяснить происхождение подготовленных изменений. Не использовать `git reset --hard` или команду, которая затрёт их. Дальнейшие выпуски должны иметь отдельную проверенную сборку и способ переключения без изменения установленной панели; это задача этапа 1.
