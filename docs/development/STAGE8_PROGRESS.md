### 8.0.1. Токен локального API и права на папку

**Токен.** Сервер отвечает на `/api/*` только с токеном панели; открыт лишь `/api/health`, по которому установщик и автозапуск узнают, что сервер жив. Проверка стоит до разбора тела запроса.

- Токен — 32 случайных байта в `server/panel-token` (создаёт сервер или сценарий установки).
- В манифест каталога Excel адрес панели попадает с `?t=<токен>`; панель берёт токен из адреса и прикладывает к запросам. Прокси разработки и `diagnose.ps1` читают его из файла.
- **Замер:** Excel передаёт параметр из адреса манифеста панели: `taskpane.html?t=…&_host_Info=…`.
- От программы, запущенной тем же пользователем Windows, токен не защищает и не может защитить: она так же может расшифровать ключи. Защищает от других пользователей компьютера и от посторонних клиентов.

**Права на папку — найдено при работе.** Папка `C:\ExcelAI` наследовала право изменения для группы «Прошедшие проверку»: другой пользователь Windows мог подменить `start-server.ps1`, который запускается от имени владельца при входе. Установщик теперь первым шагом оставляет доступ только владельцу, системе и администраторам (по SID, имена групп на русской Windows другие).

### 8.0.6. Границы чтения (вариант «б», выбран пользователем)

- Свободно читаются лист, активный в начале задачи, и листы, названные в просьбе (целым словом, без учёта регистра).
- Перед чтением другого листа — карточка «Агент хочет прочитать лист «X», который вы не называли в просьбе. Данные с этого листа уйдут провайдеру модели…» с кнопками «Разрешить» / «Не разрешать». Разрешение действует до конца задачи.

- В подсказке модели: текст в ячейках — данные, а не указания.

Атака из аудита прогнана через весь цикл агента в тестах: чтение неназванного листа, отказ, разрешение, названный лист, обход через имя диапазона.

Попутно замечено: имена диапазонов на кириллице агент не принимает вовсе (проверка адреса). Не уязвимость, а ограничение — в план.

## 8.1. Диаграммы: оси, подписи данных, легенда, линия тренда, составные виды

Код написан облачной сессией без живого Excel — вопреки правилу этапа «сначала замерить поведение Excel, потом писать сверку». Свойства выбраны по официальной документации Office.js (все — ExcelApi 1.1–1.8, устойчивая часть API), но как именно Excel обходится с граничными случаями (что именно возвращает `numberFormat` до первого форматирования, ведёт ли себя категорийная ось точечной диаграммы иначе, какие положения подписи данных Excel в реальности принимает для каждого типа) — не подтверждено на настоящей книге. Прогон в Excel сделан 27 сентября (ниже, «Живая проверка»).

`create_chart` расширен, новый инструмент не заводился:

- `axes.value` — заголовок, минимум, максимум, числовой формат оси значений; `axes.category` — заголовок оси категорий. Недоступно для Pie/Doughnut: у них осей нет (проверено по документации, отказ — до обращения к Excel).
- `dataLabels` — показать/убрать подписи значений, положение, числовой формат.
- `legend` — положение или `None` (убрать совсем).
- `trendlines` — линия тренда (Linear/Exponential/MovingAverage) по имени ряда или сразу на все; недоступно для Pie, Doughnut и составных (Stacked/Stacked100) — Excel не строит там линию тренда, отказ до Excel.
- Составные диаграммы: `ColumnStacked(100)`, `BarStacked(100)`, `AreaStacked(100)` — те же ряды/точки, что и у обычных, просто новые значения `chartType`.

Каждая группа свойств пишется и сверяется обратным чтением отдельным вызовом `context.sync()`: если Excel не принял, например, положение подписи (оно годится не для всякого типа), это не выглядит так, будто подписей нет вовсе, — сообщение называет именно эту группу. Диаграмма при этом уже построена и остаётся в отменяемом состоянии (`executionState: "applied"`), удаление всей диаграммы отменой уже покрывает и её оформление — отдельного отката под оси/подписи/легенду/тренд заводить не пришлось.

**Не сделано, перенесено:** комбинированная диаграмма «столбцы + линия». Механика другая — не свойство диаграммы целиком, а переопределение `chartType` у части рядов плюс, возможно, вторичная ось; собственной модели ожидания для «какие ряды каким типом и на какой оси» здесь ещё нет. Осталось в плане.

**Первый прогон (код облачной сессии): 3 из 4.** Оси, легенда и линия тренда Excel принял. Подписи данных — нет: сверка сочла их не включёнными.

**Замер подписей данных.** Запись на уровне диаграммы (`chart.dataLabels`) Excel принимает и распространяет на все ряды. А чтение и у диаграммы, и у ряда (`series.dataLabels`) всегда отдаёт `null` — `showValue`, `position`, `numberFormat`. Настоящее состояние видно только у ряда (`hasDataLabels`) и у подписи точки (`points.getItemAt(0).dataLabel`: `showValue`, `position`, `numberFormat`, `text`). 2. Моя ошибка при исправлении: повторная загрузка `chart.series` только с `hasDataLabels` заменила элементы коллекции, и сверка рядов упала на «свойство name недоступно». Имена теперь загружаются вместе с признаком. Подделка повторяет правило Office.js — после новой загрузки незагруженное свойство прочесть нельзя; без исправления падают 3 теста.
3. Ошибка сценария, не инструмента: когда инструмент заканчивался ошибкой, `run()` брал ответ инструмента из истории беседы — от прошлой диаграммы. Теперь ответ берётся, только если он последний в запросе.

## 8.2. Сводные: поле в столбцах, фильтры, порядок, даты

Выполнено 27 сентября 2026 года. `create_pivot_table` расширен, новый инструмент не заводился.

### Замер в Excel (Office 2021), до кода

1. **Поле в столбцах.** Шапка в две строки; с несколькими полями значений — в три. Под каждым элементом столбцов — по столбцу на каждое поле значений, в конце — итоговые столбцы по каждому полю значений («Итог Сумма по полю Сумма»). Элементы — по алфавиту. **Сочетания, которого нет в данных, Excel оставляет пустой ячейкой, не нулём.**
2. **Фильтры** (`applyFilter`, ExcelApi 1.12): «первые N» (`TopN`), «больше чем», ручной выбор элементов — все работают. **Общий итог считает только оставшееся:** после «первых 2» из трёх городов — 438 вместо 473. «Первые N» оставляют алфавитный порядок, не порядок по величине. Фильтр читается обратно через `getFilters()`.
3. **Порядок по значению** (`sortByValues`) работает; вместе с полем в столбцах — по общему итогу строки.
4. **Даты.** Поле дат в строках Excel через API сам не группирует: каждая дата — отдельная строка, подписи — серийные числа. Формулы вспомогательного столбца, записанные по-английски, Excel переводит сам (`=ГОД(A2)&" К"&ОКРУГЛВВЕРХ(МЕСЯЦ(A2)/3;0)`) и считает «2026-02», «2026 К1».
5. Два поля строк и поле в столбцах: итоги групп («2026 К1 Итог») внизу групп, как без столбцов.

### Что сделано

- `columns` — одно поле в столбцах. Сверка читает элементы столбцов из шапки и сопоставляет их **по имени, не по месту**; каждая ячейка сверяется с расчётом, пустая ячейка — где данных нет, число там же — расхождение.
- `filters` — «только эти значения» (`include`, подписи ищутся без учёта регистра, как сводит Excel; неизвестное значение — отказ со списком настоящих) и «первые/последние N» по полю значений (`top`/`bottom`, `by`). Расчёт панели: сначала выбор, затем N среди выбранного; общий итог — по оставшемуся. Равные значения на границе N — предупреждение. Поле значений передаётся в Excel по имени, прочитанному из самой сводной («Сумма по полю Сумма» — на языке интерфейса).
- `sort` — порядок элементов поля строк по итогу поля значений; в построенной сводной проверяется, что внутри каждого родителя порядок соблюдён (равные итоги — в любом порядке).
- `groupDates` — годы, кварталы, месяцы или несколько уровней сразу. Правее источника встают вспомогательные столбцы «Дата (квартал)», «Дата (месяц)» с формулами; поле дат в `rows`/`columns` заменяется ими. Формулы пишутся и **сверяются с подписями, посчитанными панелью, до построения сводной**; расхождение — столбцы убираются, сводная не строится. Текст вместо дат, числа без формата даты, занятое место правее источника — отказ до карточки. Отмена убирает сводную и вспомогательные столбцы вместе, а если столбцы после операции изменили — останавливается целиком.
- Место под сводной проверяется **по размеру до фильтров**: пока поля и фильтры добавляются по очереди, сводная бывает больше итоговой.
- Фильтры требуют ExcelApi 1.12, порядок — 1.9: без них — отказ с причиной.

**Не сделано, осознанно:** вложенные поля в столбцах; «первые N» для внутренних полей строк (Excel отбирает N внутри каждой группы — такого расчёта в панели нет); фильтры по дате самой сводной (`dateFilter`) — вместо них группировка вспомогательными столбцами.

## 8.4. Модели и аудит

Выполнено 28 сентября 2026 года.

### Замер в Excel (Office 2021), до кода

Лист с циклами четырёх видов: две ячейки по кругу, ячейка сама на себя, цикл через имя диапазона, цикл между двумя листами, и `=SUM(H:H)` в самом столбце H.
- **Ни в одной ячейке цикла Excel не показал ошибку:** везде 0 (у ячейки, посчитанной до замыкания, — 1), тип «Double». Нынешний аудит, который опирается на ошибки Excel, такие циклы не видел в принципе — их можно найти только разбором формул.
- `application.iterativeCalculation` читается (выключены, 100 итераций, 0,001).
- Имя диапазона Excel отдаёт как `=З84!$D$1` — его можно развернуть в адрес.

### Что сделано

- **Циклические ссылки** (`cycles.ts`, в `audit_workbook`): граф зависимостей между ячейками с формулами — диапазоны, целые столбцы и строки, другие листы, имена книги и листа (имя листа важнее имени книги, как в Excel). Сильно связные компоненты (алгоритм Тарьяна без рекурсии — длинные цепочки моделей не упрутся в стек); каждая — доказанная находка с цепочкой «A1 → B1 → A1» и числом ячеек. Отдельно называется, включены ли итеративные вычисления: тогда Excel не предупреждает, а значения — результат повторных пересчётов. Не видны циклы через INDIRECT/OFFSET — это сказано в отчёте.
- **Мультипликаторы** (`add_multiples`, общий исполнитель шаблонов 7.5): блок формул под таблицей компаний — EV (капитализация + чистый долг или готовый столбец EV), EV/EBITDA, EV/Выручка, P/E по каждой компании; медиана, среднее, минимум, максимум по группе. Столбцы называются по заголовкам таблицы. При нулевом или отрицательном знаменателе (убыток, отрицательная EBITDA) ячейка пустая, в медиану не входит и называется. Формат — «12,3x», EV — деньгами. Каждая ячейка сверяется с расчётом панели; отмена очищает блок.

## 8.5. Память и сохранённые сценарии

Выполнено 28 сентября 2026 года.

### Что сделано

- **Хранилище на этом компьютере** (`server/src/memoryStore.ts`): `server/memory.json` рядом с ключами, в папке надстройки, закрытой для других пользователей Windows; маршруты `/api/memory` за токеном панели. Сервер сам ограничивает число и длину записей (30 предпочтений до 200 знаков, 30 сценариев до 20 шагов), вычищает управляющие символы и переводы строк, не пишет поверх испорченного файла. Файл памяти исключён из git, из архива выпуска (проверка в CI) и из комплекта (проверка комплекта).
- **Предпочтения**: инструмент `remember_preference` (категория и одна фраза). Сохраняется **только после карточки** и **только по прямой просьбе пользователя в его сообщении** («запомни», «всегда», «по умолчанию», «впредь») — проверяет цикл агента, а не модель: подсказка «запомни…» в ячейке книги не проходит. В «Только анализ» недоступен. В начале каждой задачи предпочтения приходят модели отдельным блоком с оговоркой: просьба важнее предпочтения, а карточки, правила и границы чтения действуют как обычно.
- **Сценарии**: `save_scenario` (название и шаги-просьбы, тоже карточка и прямая просьба) и `get_scenario` (чтение). Запуск — кнопкой «Запустить» в окне «Память» или просьбой «выполни сценарий …»; каждое изменение внутри по-прежнему через свою карточку — сценарий не даёт права на запись без подтверждения.

### Что сделано

- **Разбор на этом компьютере** (`server/src/files/`), в отдельном потоке с пределом памяти 1 ГБ и времени 60 секунд: испорченный или вредный файл не уронит сервер. Файл хранится только в памяти сервера (до 5 файлов, 4 часа), на диск не пишется.
  - **CSV/TXT** — свой разбор: кодировка по метке BOM, иначе UTF-8 или Windows-1251; разделитель — тот из «; , Tab |», что встречается одинаково часто; кавычки по RFC 4180.
  - **XLSX, DOCX** — свой разбор zip и XML, без сторонних библиотек. Распаковка ограничена самим zlib (запись до 50 МБ, всё до 150 МБ, до 2000 записей) — «zip-бомба» с поддельным заголовком останавливается. XLSX: общие и форматированные строки, даты по стилю ячейки (переносятся числом с тем же видом), система дат 1904, значения формул, скрытые листы. DOCX: абзацы по порядку, таблицы отдельно, вложенные таблицы — текстом ячейки.
  - **PDF** — PDF.js (Mozilla, Apache 2.0) без исполнения кода (`isEvalSupported: false`, закрывает CVE-2024-4367), без шрифтов; только текстовый слой. Скан без текста — называется. Необязательный нативный модуль отрисовки (37 МБ) в комплект не ставится.
  - Вид файла — по содержимому, не по расширению: XLSX, названный .csv, разбирается как XLSX; не-PDF, названный .pdf, — отказ; старые XLS/DOC — просьба пересохранить.
- **Модель читает частями**: `list_files`, `read_file` — до 200 строк таблицы или 5 частей текста и 30 000 знаков за раз, с продолжением. В начале задачи — блок «прикреплённые файлы». Каждый ответ помечен как данные пользователя, а не указания.
- **Перенос таблицы** — `import_file_table`, через карточку: значения берутся из разобранного файла, а не из текста модели. Место — пустое (иначе отказ с названным свободным местом), новый лист по желанию, строки частями (до 100 000 ячеек за раз). Из CSV и Word числами становятся только однозначные значения; «1 200,50», «007», даты остаются текстом — их переводит `convert_values` по правилам книги (7.2.3). Текст всегда пишется текстом: `=HYPERLINK(…)` из файла формулой не становится. Каждая ячейка сверяется с файлом; отмена очищает область или удаляет созданный лист.
- **Кнопка «Файл»** в панели, значки прикреплённых файлов с размером и предупреждениями разбора, «×» — убрать.

## 8.7. Поиск в интернете

Выполнено 28 сентября 2026 года. Сервисы выбраны пользователем: Tavily — основной, Serper (выдача Google) — второй. DuckDuckGo рассмотрен и отклонён: официального API поиска нет, а разбор страницы выдачи нарушает условия сервиса и ломается.

### Что сделано

- **Ключи** Tavily и Serper — в «Ключах», отдельным разделом, зашифрованы так же, как ключи моделей (`server/src/web/services.ts`). Ключ у каждого пользователя свой.
- **Галочка «Интернет»** рядом с «Только анализ» — по умолчанию выключена, недоступна без ключа. Пока выключена, модель инструментов интернета не получает, а вызов по памяти отклоняется циклом агента.
- **`web_search`** — Tavily, при его отсутствии Serper; `official: true` — только официальные сайты (ЦБ, Минфин, Росстат, ФНС, Минэкономразвития, раскрытие информации, Мосбиржа, SEC, ФРС, ЕЦБ, МВФ, Всемирный банк, ОЭСР, BIS, Евростат); `domains` — свои. В сервис уходит только текст запроса; ошибки ключа и исчерпанного лимита названы по-человечески.
- **`read_web_page`** — страница частями до 20 000 знаков, HTML (таблицы строками «ячейка | ячейка», кодировки, в том числе Windows-1251), текст, PDF по ссылке (тем же разбором, что и 8.6). Кэш на 30 минут. В ответе — источник: адрес и время чтения.
- **Защита компьютера и домашней сети** (`safeFetch.ts`): только http/https, порты 80 и 443, без логина в адресе; петля, частные сети, служебные и IPv6-эквиваленты — отказ; адрес проверяется в собственной функции поиска IP **при каждом подключении**, так что имя, указывающее на внутренний адрес (DNS rebinding, `127.0.0.1.nip.io`), не проходит; перенаправления — вручную, каждое через те же проверки; пределы времени (15 с) и размера (3 МБ, в том числе после распаковки).
- **Текст страниц — данные**: к каждому ответу приложена пометка и правило источника — число из интернета записывается в книгу вместе с адресом и датой чтения. Примечаний на Office 2021 нет (8.3.4), поэтому источник — в соседней ячейке или столбце «Источник».

Найдено при работе и исправлено: без единого ключа сервер отвечал «сервиса "undefined" нет» — теперь «добавьте ключ»; таблица ЦБ приходила по ячейке на строку, потому что переводы строк исходника HTML считались значимыми — теперь строки таблицы собираются; сборка панели однажды пропустилась из-за упавшего теста, и галочки у пользователя не было — пересобрано.

### Проверки

- Автоматические: 7 тестов сервера — адреса (IPv4, IPv6, отображённые), отказы до запроса, имя с внутренним адресом при подключении, разбор HTML и таблица как на cbr.ru, поиск Tavily и Serper на подставных ответах (домены, ключи, запасной сервис, 401, 429, нет ключа), чтение частями и кэш со страницей с «инструкцией ассистенту»; тест цикла агента: при выключенной галочке инструменты не выдаются и вызов отклоняется. `npm run check`: 522 клиентских, 91 серверный, сборка.

## 8.8. Распространение

Начато 26 сентября, установка проверена у пользователя 27 сентября 2026 года.

### 8.8.1. Удаление

`Удалить.cmd` → `scripts/uninstall.ps1`. Отказывается работать, пока открыт Excel. Останавливает сервер этой папки, снимает автозапуск и регистрацию в Excel, удаляет записи надстройки из кэша Office. Сертификат и папку с ключами удаляет только после вопроса. Трогает лишь то, что указывает на эту папку. Проверено у пользователя: `C:\ExcelAI` удалена начисто.

### 8.8.2. Регистрация без прав администратора — не достигнута

Замысел был заменить каталог `\\localhost\C$\…` (служебная папка диска открыта только администраторам) записью в `HKCU\…\WEF\Developer`. Туда может писать любой пользователь, и формат записи совпадает с тем, что пишет инструмент Microsoft `office-addin-dev-settings`.

**Замер 27 сентября** (установка через `Setup.exe`, Excel перезапущен): Excel запись не прочитал. В кэше Office не появилось ни одной записи надстройки, в «Моих надстройках» нет раздела «Надстройки разработчика», на ленте кнопки нет. Инструмент Microsoft после такой записи открывает книгу, в которую надстройка уже вставлена (`store="developer"`). Такую книгу я собрал и открыл: Excel прочитал манифест, но надстройку всё равно не показал. Раньше лента у пользователя работала только из каталога — регистрация «для разработчика» ни разу не была проверена в Excel, CI проверял лишь запись в реестре.

**Решение:** `scripts/register-addin.ps1` снова регистрирует каталог, если `\\localhost\<диск>$\…\catalog` читается (учётная запись с правами администратора — обычный домашний компьютер). Иначе пишет запись «для разработчика» и честно предупреждает, что Excel может надстройку не показать. CI проверяет любой из двух способов и печатает, какой сработал. Установка для пользователя без прав администратора остаётся открытым вопросом; возможный путь — каталог через WebDAV с локального сервера, не проверялся.

### 8.8.3. Проверка обновлений

Сервер: `/api/update` раз в сутки спрашивает GitHub о последнем выпуске, неудачный ответ помнит час. Ссылка принимается только на github.com. `UPDATE_CHECK=off` выключает проверку. Панель показывает полосу «вышла версия X» со ссылкой. Ключи и настройки при установке поверх сохраняются: `Setup.exe` не трогает `server/keys.dpapi` и `server/panel-token`.

### 8.8.4. `Setup.exe`

Inno Setup, `packaging/ExcelAI.iss`, собирается в GitHub Actions. Ставит в `%LOCALAPPDATA%\Programs\ExcelAI` без прав администратора. Не запускается, пока открыт Excel; перед копированием останавливает сервер этой папки. После копирования запускает `install.ps1` (журнал — `install.log`). Удаление — через «Приложения» Windows, запускает `uninstall.ps1`. Установщик не подписан — SmartScreen покажет «Неизвестный издатель»; подпись — решение пользователя (платный сертификат).

Найдено при проверке в CI и исправлено:
- Windows PowerShell 5.1 портил кириллицу в шагах CI — шаги переведены на PowerShell 7;
- в тихом режиме установщик висел на окне сертификата — ключ `/skipcert=1`, только для CI;
- `Start-Process -Wait` в PowerShell 7 ждал и сервер, запущенный установкой, — ожидание только самого процесса;
- `PSModulePath` из PowerShell 7 ломал модули Windows PowerShell 5.1 в сценариях — сценарии его восстанавливают;
- окна сообщений не подавлялись в тихом режиме — `SuppressibleMsgBox`.

### Проверки 8.8

- CI: сборка `Setup.exe`, тихая установка и удаление на чистой Windows (после удаления нет задачи, регистрации, папки и сервера), установка из zip.
- У пользователя: «Удалить.cmd» снял установку 1.0.3 из `C:\ExcelAI`. `Setup.exe` поставил в личную папку (6/6), сервер отвечает. После перехода на каталог надстройка добавлена из «Общей папки», панель открылась, ключи на месте.

## 8.1 (завершение). Комбинированная диаграмма

Выполнено 28 сентября 2026 года.

**Замер:** `series.chartType` и `series.axisGroup` (ExcelApi 1.7–1.8) Excel принимает и читает обратно; вторая ось — `axes.getItem("Value", "Secondary")`, её заголовок и формат пишутся и читаются. Общий тип диаграммы после смены типа ряда Excel отдаёт как `null`. Тип «круговая» у ряда столбцов Excel молча принимает — такое сочетание бессмысленно.

**Сделано:** `create_chart` + `combo` — тип отдельных рядов (столбцы, линия, линия с точками, область) и перенос на вторую ось; `axes.secondary` — её заголовок, границы, формат. Основа — столбцы, составные столбцы, график или области; остальное, ряд не из шапки, вторая ось без ряда на ней — отказ до Excel. Тип и ось каждого ряда сверяются обратным чтением.

**Проверки:** 2 теста (комбинированная с форматом второй оси; ряд, оставшийся на основной оси, назван; отказы). В Excel (`node scripts/live-excel-stage7.mjs 8.1к`) — 2 из 2 с первого прогона. DeepSeek: «выручка столбцами, рентабельность линией на отдельной оси справа в процентах» — одна карточка, в книге ряды и формат 0 % второй оси совпали.

## После закрытия этапа: история беседы при сохранении книги (1.0.14)

Найдено пользователем 28 сентября 2026 года: после первого сохранения книги чат исчезал. Беседа была привязана к адресу книги, а он при первом сохранении и «Сохранить как» появляется или меняется. При сохранении в OneDrive Excel ещё и перезапускает панель — беседа несохранённой книги нигде не хранилась, найти её было нечем.

Исправлено двумя шагами:
1. Смена адреса, пока панель открыта, — это сохранение той же книги (панель Office не переходит в другую книгу): беседа переносится под новый адрес. У пользователя этого не хватило — панель перезапускалась.
2. В настройки документа (Office Settings, сохраняются в файле) перед первым сообщением пишется случайный номер беседы; переписка остаётся только на этом компьютере и ищется по номеру, а для старых бесед — по адресу. Чужая книга с чужим номером ничего не откроет: такой переписки здесь нет. Восстановленная беседа, как и раньше, начинается в «Только анализ».

Проверено у пользователя: новая книга, сообщение агенту, сохранение в OneDrive — переписка на месте, агент продолжает работу. Тесты: решение привязки и номер в книге (запись один раз, повторное чтение, чужое значение и неудачная запись).

## После закрытия этапа: установка без прав администратора (1.0.16)

Открытый вопрос 8.8.2 закрыт. Excel показывает надстройку только из «Общей папки» — сетевой папки каталога. Прежде это была служебная `\\localhost\C$\…`, доступная только администраторам; запись «для разработчика» Excel не показывает.

Решение — тот же каталог через WebDAV. Сервер надстройки отдаёт папку `catalog` на `http://127.0.0.1:3080`, Windows (служба WebClient) открывает её как сетевую папку `\\localhost@3080\catalog`, права администратора не нужны. Проверено у пользователя дважды — проверочным сервером и рабочим: кэш надстроек Excel очищен, «Общая папка» → надстройка → «Добавить» → панель открылась; в журнале — чтение манифеста через WebDAV.

Защита:
- только чтение, только файлы прямо в папке каталога, только 127.0.0.1; заголовков CORS нет;
- Host должен быть `localhost:3080` или `127.0.0.1:3080` — иначе 403: страница с подменой DNS (rebinding) манифест с токеном не прочитает;
- каталог открыт, только когда регистрация выбрала этот путь: `register-addin.ps1` ставит метку `server\catalog-dav` (папка закрыта правами владельца), если `C$` недоступна, и снимает её при регистрации через `C$`. Без метки — 404: у администратора другие учётные записи этого компьютера манифест по WebDAV не видят.

Порядок регистрации: `C$` → WebDAV → «для разработчика» (если служба WebClient выключена). Удаление снимает каталог и по постоянному Id — в адресе WebDAV пути к папке нет. `-SkipAdminShare` проверяет путь без администратора на компьютере, где права есть. CI: при установке через `C$` каталог по WebDAV закрыт (404); с меткой — манифест своему адресу и 403 чужому; регистрация через WebDAV — если на машине сборки есть служба WebClient. Тесты: 6 на WebDAV-обработчик (список, чтение, выход за папку, только чтение, чужой Host, метка).
