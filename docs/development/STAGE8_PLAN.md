## Вне этапа

- Bloomberg, FactSet, Capital IQ, Refinitiv — требуют подписки и доступа к API у пользователя; обещать всем нельзя.
- Передача в PowerPoint и Word — это отдельные надстройки в тех программах, фактически новые продукты.
- Excel в браузере и на Mac — нужен сервер в интернете вместо локального; отдельное решение об архитектуре.
- Проверка на своём сервере (Qwen) — перенесена с этапа 7, выполняется, когда сервер появится.
- Макросы VBA, расписание, письма, таблицы данных «Что если» — не входят и в эталонный список.

## Очерёдность работ

### 8.0. Безопасность — вход в этап

Без этого среза внешние данные (8.6–8.7) не начинаются: они приносят в контекст модели чужой текст, и цена ошибки растёт.

1. **Авторизация локального API.** Сейчас сервер отличает панель от прочих клиентов только по сетевому адресу и заголовкам браузера; программа на том же компьютере может тратить ключ пользователя и менять сохранённые ключи. Нужен случайный токен сеанса, который получает только панель, проверка на всех `/api/*` до разбора тела, ограничение числа одновременных запросов к провайдеру.
2. **Полная копия книги — только с подтверждением.** `create_workbook_backup` сейчас числится чтением и работает без карточки, даже в «Только анализ». Сделать отдельным видом операции «файл на диске» с карточкой.
3. **Отмена загрузки копии** удаляет только файл своей активной загрузки, идентификатор проверяется.
4. **Привязка истории к книге** — по полному адресу книги, а не по короткому отпечатку; при смене книги история и разрешение записи сбрасываются.
5. **Зависимости** — обновить инструменты разработки и транзитивные пакеты сервера, прогнать все проверки.
6. **Границы чтения** (решение пользователя до начала). Сейчас модель может прочитать любой лист, и защита от текста в ячейках, уговаривающего прочитать лишнее, держится на поведении модели. Варианты:
   - а) чтение только листов, названных в просьбе, остальное — по карточке;
   - б) свободное чтение активного листа, карточка при первом обращении к другому листу в задаче;
   - в) как сейчас, но с явной строкой в панели «прочитаны листы: …» и возможностью запретить лист.

Каждое исправление — сначала тест, который показывает пробел на текущей сборке, затем исправление и тот же тест зелёным.

### 8.1. Диаграммы

Оси (заголовки, минимум и максимум, формат чисел), подписи данных, положение легенды или её отсутствие, линия тренда (линейная, экспоненциальная, скользящее среднее), составные столбцы и комбинированная диаграмма «столбцы + линия». Сверка — обратным чтением каждого заданного свойства. Замер до кода: какие свойства ExcelApi 1.14 отдаёт обратно и в каком виде.

### 8.2. Сводные

Поля в столбцах, фильтры полей (значения, верхние N), сортировка по значению, группировка по месяцам и кварталам через вспомогательный столбец одной операцией. Панель по-прежнему заранее считает итоги и сверяет с построенным — теперь и для полей столбцов. Замер: как сводная сводит подписи в столбцах и как фильтр меняет итоги.

### 8.3. Оформление, текст, печать, примечания, листы

1. Наборы значков в условном форматировании; сверка правила, а не вида ячейки, как в 7.4.3.
2. Смена регистра: ПРОПИСНЫЕ, строчные, «Как в предложении», «Каждое Слово» — по образцу `trim_text`: пары «было → станет», текст остаётся текстом, отмена.
3. Печать: область печати, ориентация, поля, масштаб «вписать в N страниц», колонтитулы, повторяемые строки заголовков. Отмена — возврат прежних параметров страницы.
4. Примечания к ячейкам. На Office 2021 в API есть только комментарии-обсуждения (ExcelApi 1.10), примечания старого вида — с 1.18. Выдавать то, что есть в установленном Excel, и называть, что создано. Главный сценарий — источник числа рядом с числом.
5. Копирование листа: замерить на Microsoft 365. Если там работает — выдавать только там, где работает; обход «визуально похожим» копированием не делать.

### 8.4. Модели и аудит

1. Сравнение компаний с мультипликаторами: EV/EBITDA, EV/Выручка, P/E по каждой компании и медианы по группе; все входы — ячейки, как в моделях 7.5.
2. Циклические ссылки в аудите: граф зависимостей по разобранным формулам, замкнутые цепочки — доказанная находка с адресами; включённые итеративные вычисления книги — называются.
3. Источник допущения в модели — примечанием к ячейке допущения (после 8.3.4).

### 8.5. Память и сохранённые сценарии

1. Предпочтения пользователя: форматы чисел, стиль заголовков, цвета, оформление диаграмм. Хранятся на этом компьютере рядом с ключами, видны и редактируются в панели; модель получает их коротким блоком в начале задачи. Ничего не запоминается молча: панель предлагает сохранить и показывает, что сохранено.
2. Сохранённые сценарии: последовательность просьб, которую человек назвал и запускает командой. Каждое изменение внутри сценария — по-прежнему через карточку; сценарий не даёт права на запись без подтверждения.

### 8.6. Загрузка файлов

CSV, XLSX, PDF и DOCX в панели. Разбор — на локальном сервере, файл никуда не отправляется целиком: модель получает разобранную таблицу или текст частями, как при чтении листа. Перенос в книгу — через существующие инструменты записи с карточкой. Содержимое файла — недоверенные данные: инструкции внутри файла не выполняются, это проверяется тестом с заведомо вредным текстом. Лимиты размера и числа страниц.

### 8.7. Поиск в интернете

Инструмент поиска и чтения страниц на локальном сервере через сервис поиска; ключ сервиса — в «Ключах», как у провайдеров. Только чтение. Каждое число из интернета попадает в книгу с источником (адрес и дата) в примечании. Режим «официальные источники» — список доменов (сайты для инвесторов, регуляторы). Текст страниц — недоверенные данные, как файлы в 8.6. По умолчанию выключено; включение — явное действие пользователя в панели.

### 8.8. Распространение

1. «Удалить.cmd»: автозапуск, регистрация в Excel, по желанию — сертификат и сохранённые ключи.
2. Установка без прав администратора: регистрация надстройки без общей папки `\\localhost\C$`, доступной только администраторам.
3. Проверка обновлений в панели: «вышла версия X» со ссылкой; обновление сохраняет ключи и предпочтения.
4. `Setup.exe` (Inno Setup в GitHub Actions); цифровая подпись — отдельное решение пользователя (платный сертификат).
5. Проверка комплекта на Microsoft 365 — второй сборке Excel после Office 2021.

## Правила, которые переходят из этапа 7

- Сначала замерить поведение Excel, потом писать сверку. Замер записывается в отчёт.
- Каждый изменяющий инструмент — через реестр планов: план, карточка, проверка состояния, запись, обратное чтение; `destructive: true`, тест реестра.
- Возможности проверяются по версии API установленного Excel; неподдерживаемое не выдаётся модели.
- Найденный дефект показывается на прежней сборке до исправления.
- Каждый срез: автоматические тесты, живые сценарии в Excel (`scripts/live-excel-stage7.mjs` → сценарии этапа 8), просьбы обычными словами на DeepSeek; для внешних данных — ещё и проверка вредного текста.
- Итоговый текст модели панель не сверяет; где можно — панель сама называет числа (как в шаблонах 7.5).
- Каждый выпуск — через GitHub Actions; архив проверяется на ключи перед публикацией ссылки.

## Критерии готовности

Срез закрыт, когда его инструменты проверены в Excel, записаны в отчёт `STAGE8_PROGRESS.md` с замерами, README обновлён, выпуск опубликован. Этап закрыт, когда закрыты 8.0–8.8 или явно перенесены решением пользователя с записью причины.
