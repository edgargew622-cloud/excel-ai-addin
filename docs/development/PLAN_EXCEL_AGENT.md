# План улучшения Excel-агента

Дата: 14 сентября 2026 года. Статус: проект плана для обсуждения; реализация не начата.

## Цель

Агент должен понимать структуру открытой книги, находить нужные данные и безопасно предлагать изменения. Он не должен угадывать адреса, принимать цвет ячейки за разрешение на запись или автоматически отправлять всю книгу провайдеру ИИ.

Сейчас надстройка предоставляет модели девять инструментов. Читать содержимое книги она может только через `get_range_values` по явно указанному адресу. Активный лист надстройка определяет в начале задачи, но не передаёт модели отдельным обзором. Частичный custom undo уже есть; для структурных операций вроде удаления строк его нет.

## Этап 0. Надёжная работа надстройки

**Проблема:** если локальный сервер останавливается, Excel показывает общую ошибку загрузки надстройки, а не объясняет причину.

Что сделать:

- Проверить автозапуск после входа в Windows и независимость серверов от окна терминала.
- Добавить контроль состояния обоих локальных сервисов и автоматическое восстановление после неожиданной остановки. Не запускать вторую копию, если порты уже заняты рабочим экземпляром.
- Для работающей панели показывать состояние подключения к API и понятную команду повторного соединения. Если сам сервер страницы недоступен, диагностика должна оставаться доступной через отдельный локальный проверочный сценарий: панель в этом случае не может нарисовать собственную ошибку.
- Писать в диагностический журнал причины остановки и время перезапуска, но не содержимое ячеек и не API-ключи.

**Готово, когда:** после перезагрузки ПК надстройка открывается без ручного запуска команд; после аварийной остановки сервера он восстанавливается, а пользователь видит понятный статус.

## Этап 1. Карта книги и текущий контекст

Добавить инструменты только для чтения:

| Инструмент | Что возвращает |
| --- | --- |
| `list_sheets` | Название, порядок, видимость и состояние защиты каждого листа. |
| `get_active_context` | Активный лист, выделенный диапазон и активную ячейку на момент запроса. |
| `get_sheet_overview` | Границы занятой области, примерный размер, таблицы и их столбцы, именованные диапазоны, диаграммы и сводные без выгрузки всех значений. |

Правила:

- Перед ответом на вопрос о книге или перед изменением агент сначала получает краткую карту, затем читает только нужные участки.
- Если есть лист «Инструкция», «Начало» или похожий, агент рассматривает его как возможный источник правил, но проверяет его содержание; наличие такого листа не предполагается заранее.
- Для длинных списков вводятся лимит выдачи и постраничный просмотр. Скрытые листы отмечаются явно.
- Для операций записи целевой лист фиксируется до подтверждения, чтобы переключение вкладки пользователем не перенаправило правку.

**Готово, когда:** агент без догадок отвечает, сколько в книге листов, какой активен, что выделено и где находятся основные таблицы.

## Этап 2. Адресный поиск и чтение структуры

- `search_workbook(query, scope, limit)`: поиск по выбранному листу или всей книге, с адресами результатов и ограничением объёма. Отдельно оговорить поиск в значениях и формулах.
- `get_range_details`: для небольшого диапазона читать нужные по задаче свойства — формулы, числовой формат, заливку, шрифт, объединения, правила проверки ввода, защиту ячеек и условное форматирование. Не загружать все свойства при каждом вызове.
- `get_comments`: читать современные комментарии и их местоположение, если API поддерживается.
- `find_cell_errors`: выдавать адреса и виды ошибок формул в ограниченной области, не сканируя без предупреждения огромную книгу.
- Для больших книг читать данные порциями, показывать прогресс и останавливать поиск по запросу пользователя.

**Совместимость:** старые примечания Excel и современные комментарии — разные объекты. API примечаний появился в ExcelApi 1.18. На проверенной версии Excel этого ПК (`16.0.14334.20906`) его нельзя обещать без обновления Office или отдельного альтернативного механизма. Возможность проверять при запуске через `Office.context.requirements.isSetSupported`; недоступный инструмент не показывать модели.

**Готово, когда:** агент находит заданный текст по книге, указывает точные адреса и отличает значение ячейки от формулы, оформления и комментария.

## Этап 3. Предпросмотр и защита правок

Перед изменением:

1. Прочитать целевой диапазон и его существенные свойства.
2. Показать человеку понятный план: лист, адрес, сколько ячеек или строк затронуто, примеры «было → станет», формулы и ограничения, которые могут быть затронуты.
3. Перед исполнением повторно сверить исходное состояние. Если пользователь изменил ячейки после предпросмотра, отменить операцию и подготовить новый план.
4. Требовать явного подтверждения для удаления строк, перезаписи формул и других потенциально необратимых действий.
5. После записи перечитать результат и показать фактический diff. Ошибку выполнения не выдавать за успешную правку.

Отдельно добавить **правила для конкретной книги**: пользователь может указать допустимые для правки листы и диапазоны (например, только столбец H). Оформление вроде синей заливки — подсказка, но не доказательство права на запись. Режим «Только анализ» должен запрещать все изменяющие инструменты на уровне исполнения, а не только текстовой инструкции модели.

Не обещать универсальный Ctrl+Z: существующий custom undo покрывает лишь часть операций. Для структурных изменений сохранить отдельные предупреждения и рассмотреть резервную копию книги до выполнения, если это можно сделать надёжно в данном окружении.

**Готово, когда:** агент не перезаписывает формулу или недопустимый диапазон без явного решения пользователя; перед любой опасной правкой видно её влияние; после правки есть проверяемый отчёт.

## Этап 4. Поведение агента, приватность и испытания

- Обновить системные правила: сначала обзор, затем адресное чтение; явно разделять факт из книги, вывод и предположение; проверять вычисленный результат формулы, а не только её текст.
- Ограничивать объём передаваемых модели данных. Показывать, какие диапазоны будут отправлены внешнему провайдеру; не отправлять всю книгу автоматически. API-ключи и значения ячеек не включать в обычные технические логи.
- Добавить тестовые книги: пустая; с десятками листов; со скрытыми и защищёнными листами; с формулами и ошибками; с объединениями, таблицами и комментариями; с большим занятым диапазоном.
- Проверять не только unit-тесты, но и работу в установленном Excel на этом ПК: открытие панели, поиск, предпросмотр, отказ от правки, подтверждение, проверку результата и перезапуск Windows.

**Готово, когда:** агент стабильно выполняет типовые задачи на тестовых книгах, не выдумывает листы и адреса, а ограничения среды показывает честно.

## Предлагаемый порядок реализации

1. Сначала этап 0 — без надёжной загрузки остальные улучшения недоступны пользователю.
2. Затем этап 1 и минимальная часть этапа 3: карта книги, текущий контекст и безопасный предпросмотр записи. Это первый полезный релиз.
3. Затем поиск и подробное чтение из этапа 2.
4. После этого — расширенная диагностика, приватность и испытания из этапа 4.

Основные места изменений: `src/excel/toolSchemas.ts` (контракты инструментов), `src/excel/excelTools.ts` (операции Excel), `src/agent/loop.ts` (поведение и проверки), `src/taskpane/Taskpane.tsx` (статусы и предпросмотр), `scripts/start-excel-ai-addin.cmd` и сценарии автозапуска (надёжность). Существующие ограничения размера чтения и безопасной отмены сохранять, пересматривать только по результатам измерений.
