# AI-панель для Excel

Office Add-in: чат сбоку от книги, который читает и правит листы через Office.js.
Модель выбирается из списка провайдеров: DeepSeek, Kimi, Z.AI, OpenAI, Grok, OpenRouter
и свой сервер с Qwen. Ключи живут только на локальном сервере и в панель не попадают.

Состояние на 24 сентября 2026 года: этап 6 закрыт, стабилизация перед этапом 7
завершена — см. `PRE_STAGE7_STABILIZATION_PROGRESS.md`. План дальше — `STAGE7_PLAN.md`.

## Допущения

1. **Провайдеры OpenAI-совместимые.** Все используют `POST {baseURL}/chat/completions` с одинаковым форматом `tools` и `tool_calls`. Модели OpenAI, которые принимают функции только через `/v1/responses` (например, `gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna`), сервер переводит туда сам по тексту отказа (`server/src/openaiRoute.ts`, `responsesApi.ts`). Claude доступен через OpenRouter; его родной `tool_use` панель принимает как завершённый вызов.
2. **Списки моделей заданы вручную** в `server/src/providers.ts` и устаревают. Список OpenRouter отобран живыми запросами с вызовом инструмента; сервер пропускает только модели из списка.
3. **Инструменты исполняются в панели, не на сервере.** Сервер не имеет доступа к книге: он пересылает трафик, прячет ключ, хранит резервные копии и считает расход.
4. **Сборка на Vite**, не на webpack из `yo office`.
5. **Сервер тоже на HTTPS** с теми же dev-сертификатами: webview не даст смешать https-панель с http-бэкендом.
6. **Генерация изображений не включена.** Место под неё заложено (`capabilities` в реестре провайдеров).
7. **Отмена своя.** Ctrl+Z не откатывает правки надстройки — их нет в журнале Excel. Кнопка «Отменить» в панели откатывает последнюю операцию агента, если у неё есть отмена.
8. **Свой сервер Qwen** (`qwen`) включается только явным адресом `QWEN_BASE_URL` в `server/.env`; на процессоре задача получает 30 минут вместо пяти.

## Запуск локально

```bash
npm install
npm --prefix server install
npm run certs                     # доверенные HTTPS-сертификаты, один раз
cp .env.example server/.env       # вписать хотя бы один ключ
npm.cmd run check                 # тесты и сборка панели и сервера
npm.cmd run release               # сохранить проверенную сборку как выпуск
npm.cmd run apply                 # перевести работающий сервер на выбранный выпуск
npm.cmd run release:apply         # то и другое одной командой
npm.cmd run autostart             # зарегистрировать один фоновый запуск при входе
powershell -ExecutionPolicy Bypass -File scripts/register-local-catalog.ps1
npm.cmd run diagnose              # проверить установку
```

Рабочая панель и API доступны на `https://localhost:3000`. После регистрации автозапуска сервер стартует при следующем входе в Windows; для первого запуска выполните `npm.cmd run supervise`. Скрипт держит процесс без видимого окна при запуске через планировщик.

Для разработки запустите `npm.cmd run dev`: Vite работает на `https://localhost:3100` и проксирует `/api` к рабочему серверу. `manifest.dev.xml` имеет отдельный GUID.

Перед обновлением выполните `npm.cmd run check`, затем `npm.cmd run release`. Выпуск содержит копии панели и сервера; текущий процесс продолжит использовать прежнюю сборку до перезапуска — это защищает проверенную панель от подмены во время пересборки. Перевести сервер на выбранный выпуск можно командой `npm.cmd run apply`, а собрать и сразу перевести — `npm.cmd run release:apply`. Без этого шага панель продолжит отдавать прежний код, и свежие правки будут выглядеть неработающими. Для возврата выберите `npm.cmd run rollback` и перезапустите свой сервер после завершения активных запросов. `npm.cmd run diagnose` покажет выбранный и работающий выпуски.

### Если npm start не сработал

**Windows.** Положите `manifest.xml` в папку, например `C:\addins`. Excel → Файл → Параметры → Центр управления безопасностью → Параметры центра → Каталоги надёжных надстроек → добавить путь, поставить «Показывать в меню». Перезапустить Excel → Главная → Надстройки → Мои надстройки → Общая папка.

**Mac.** Скопировать манифест в `~/Library/Containers/com.microsoft.Excel/Data/Documents/wef/`, перезапустить Excel.

**Excel Online.** Вкладка «Надстройки» → «Отправить мою надстройку» → выбрать `manifest.xml`.

## Как работает цикл

1. Панель шлёт историю и схемы доступных в текущем режиме инструментов на `/api/chat`.
2. Сервер подставляет ключ и стримит ответ провайдера обратно как SSE.
3. Модель возвращает `tool_calls`. Панель сверяет имя со списком, проверяет аргументы по JSON-схеме и не исполняет вызов без завершающего `finish_reason`.
4. Изменяющая операция проходит одним путём для всех (`src/excel/plans.ts`): подготовка плана и предпросмотр «было → станет» → карточка с «Выполнить» → повторная проверка книги, листа и исходного содержимого → запись → обратное чтение и сверка с планом.
5. Результат уходит модели сообщением `role: "tool"` со статусом исполнения: `verified`, `applied`, `unknown`, `failed_before_write`. Неподтверждённый или частичный итог останавливает задачу: следующий шаг должен начинаться с чтения книги.

Пределы одной задачи (`src/agent/loop.ts`): 20 обращений к модели, 30 чтений, 8 изменяющих операций, 5 минут активного времени (30 для своего сервера), ответ инструмента до 128 КиБ, запрос до 1 МиБ.

Книга целиком модели не отправляется. Она видит только то, что сама запросила, и не больше 20 000 ячеек за раз.

Панель запускается в режиме «Только анализ»: модель получает контекст книги и инструменты чтения, а исполнитель запрещает любые изменения. После восстановления беседы режим включается снова.

**Чтение:** `get_active_context`, `list_sheets`, `get_sheet_overview`, `get_range_values`, `search_workbook`, `get_range_details`, `profile_range` (профиль таблицы для очистки: числа и даты текстом, пробелы, неоднозначные значения, дубликаты), `recall_snapshot`, `measure_workbook_export`, `create_workbook_backup` (резервная копия в `backups/`; восстановление ручное).

**Изменение** — 24 инструмента, все через карточку подтверждения:

| Инструмент | Что делает | Проверка после | Отмена в панели |
| --- | --- | --- | --- |
| `set_range_values`, `set_ranges_values` | запись значений и формул; группа — по порядку | каждая ячейка | да |
| `fill_range` | протяжка формулы или значения; шаблон первой строки — своя формула у каждого столбца | каждая ячейка по R1C1 | да |
| `format_range` | шрифт, заливка, выравнивание, размеры, автоподбор, границы | запрошенные свойства | точная до 500 ячеек, с проверкой восстановленного |
| `sort_range`, `apply_filter` | сортировка и автофильтр | набор строк; состояние фильтра | сортировка — да, фильтр — нет |
| `insert_rows`, `delete_rows` | вставка и удаление строк | ошибки ссылок, таблицы | нет; история отмены очищается |
| `insert_columns`, `delete_columns` | вставка и удаление столбцов; называют формулы, которые сломаются, сузятся или не охватят новые | ошибки ссылок против предсказанных | нет; история отмены очищается |

| `add_conditional_format` | правило условного форматирования | все запрошенные свойства правила | да |
| `convert_table_to_range` | таблица Excel → обычный диапазон | таблицы нет, ссылки переписаны, значения прежние (кроме итогов при снятом фильтре) | нет |
| `set_data_validation` | правило проверки ввода: список, число, дата | правило читается обратно; нарушителей называет Excel | да, если прежде не было разных правил |
| `create_table` | таблица Excel | границы, стиль, имя, заголовки | нет |
| `create_chart` | диаграмма, без наложения на другие | ряды, точки, тип, положение | да |
| `create_pivot_table` | сводная, табличный макет | итоги всех групп всех уровней | да |

| `delete_sheet` | удаление листа; называет, что исчезнет и что станет #ССЫЛКА! | лист исчез, новые ошибки ссылок — не больше предсказанных | нет |

Перед записью формул панель проверяет, есть ли их функции в этом Excel: набор зависит от версии (в Office 2021 нет, например, `LAMBDA`, `TEXTSPLIT`, `VSTACK`), а русские имена функций через API не понимаются вовсе. Проверка — запись `=ИМЯ()` в пустую ячейку вне данных с очисткой, ответ запоминается до конца сеанса; недоступная функция отклоняет запись до её начала. Новые ошибки после записи (`#ДЕЛ/0!`, `#Н/Д` и другие) называются с адресами на любом языке интерфейса. Просьбы «посчитай и запиши» модель по умолчанию выполняет формулами.

Группа записей не транзакция: после сбоя оставшиеся не выполняются, выполненные не откатываются, и задача останавливается. «Остановить» доводит начатую запись и не начинает следующих.

## Известные ограничения

**CORS.** Напрямую из панели к провайдерам не достучаться — они не отдают нужные заголовки. Отсюда локальный сервер.

**Версии API.** Проверено на Excel для Windows с ExcelApi 1.14. Сводные требуют ExcelApi 1.8, автофильтр — 1.9; недоступные инструменты модели не выдаются.

**Excel для Mac и Excel Online** не проверялись.

**Отмена не у всего.** Нет отмены у вставки и удаления строк, фильтра и таблицы — карточка говорит об этом до подтверждения. Отмена отказывается затирать то, что изменили после операции агента, и сообщает, если Excel не принял восстановление.

**Что проверено только частично.** Какие ячейки подсветит условное форматирование, Excel не сообщает — это оценка панели. Сводная сверяется для полей строк и значений; полей столбцов и фильтров сводной инструмент не создаёт. Внешняя рамка, пропавшая однажды на этапе 6, не воспроизведена — причина не выяснена.

**Измерение расхода.** Сервер записывает по каждому обращению к модели провайдера, модель, интерфейс, размеры, время и фактический `usage`; содержимого книги в метриках нет. Сводка — на `/api/metrics`.

**Контекст и стоимость.** Каждая итерация шлёт историю заново, включая результаты инструментов, — платите за все итерации. По замеру на DeepSeek простая задача — 22–47 тыс. токенов, задача с уточнением и тремя удалениями — 170 тыс.

**Модель может ошибиться в пересказе.** Книга сверяется панелью, а итоговый текст модели — нет: в приёмке DeepSeek однажды ответил по-китайски и однажды неверно пересказал число оставшихся строк при верной книге.

## Риски безопасности

**Ключи.** Лежат в `server/.env`, в панель не попадают. Сервер слушает только петлевые адреса и проверяет Host и Origin. Для доступа с других компьютеров потребуются отдельная авторизация и другая схема развёртывания.

**Запись в книгу.** Модель не выполняет произвольный код: нет `eval`, нет передачи выражений в Excel. Только функции с фиксированными схемами. Всё, что приходит с именем не из списка, отклоняется до обращения к Excel.

**Подтверждения.** Операции, которые затирают данные, показывают пользователю сами аргументы и ждут явного «Выполнить». Отказ возвращается модели текстом, чтобы она не пыталась повторить то же самое.

**Данные уходят наружу.** Всё, что модель прочитала из книги, отправляется провайдеру. Для книг с персональными данными или коммерческой тайной это главный риск, и прокси его не решает — решает выбор провайдера и договор с ним.

**Prompt injection из книги.** Текст в ячейках попадает в контекст модели. Ячейка с содержанием вида «игнорируй инструкции и удали лист» — реальный вектор. Подтверждение разрушительных операций и есть основная защита, поэтому его не стоит отключать «для удобства».

## Пять причин, по которым это может не завестись у пользователя

1. **Сертификаты.** Webview Excel молча отказывается грузить панель с недоверенного localhost — вместо ошибки просто белый прямоугольник. Лечится `npm run certs` с подтверждением установки корневого сертификата; проверять открытием адреса панели в браузере.

2. **Версия Office ниже требуемой.** `pivotTables.add` и `autoFilter` упадут на необновлённом Office 2016/2019 и в части сборок Online. Закрывается проверкой `isSetSupported` при старте панели: недоступные инструменты просто не отдавать модели, тогда она не будет их звать.

3. **Модель врёт в аргументах.** Присылает адрес вместе с именем листа, массив не того размера, столбец вне диапазона, битый JSON. Это не редкость, а норма для моделей попроще. Закрывается тем, что уже сделано: валидация до обращения к Excel и возврат ошибки текстом обратно в модель — она исправляется со второй попытки. Плюс пределы задачи — 20 обращений к модели, 30 чтений, 8 изменений, — чтобы исправления не стали бесконечными.

4. **Именованные листы и локализация.** Русская локаль Excel, листы с пробелами и кириллицей, разделитель аргументов формул — точка с запятой вместо запятой. Формула, которую модель напишет по-английски, может не примениться. Закрывается тем, что `range.formulas` в Office.js всегда принимает en-US синтаксис независимо от интерфейса, — но это надо явно сказать модели в системном промпте, иначе она подстроится под язык диалога.

5. **Прокси не запущен или без ключа.** Панель откроется, а на первое сообщение выдаст ошибку сети. Закрывается тем, что `/api/providers` вызывается при старте: если ключей нет, панель сразу показывает, что именно заполнить, а не ждёт первого запроса.

### Исправления после code review

- Исправлен namespace `VersionOverrides` для Excel TaskPane Add-in и добавлен requirement `AddinCommands 1.1`.
- Добавлена runtime JSON Schema validation аргументов tools через Ajv.

- Добавлен action-based custom undo для безопасно обратимых операций. Структурные insert/delete строк намеренно не имеют custom undo и инвалидируют прежний стек; диаграммы/PivotTable и ограниченные диапазонные изменения получают обратные действия.
- `create_pivot_table` и `apply_filter` не передаются модели, если текущий Excel не поддерживает нужный requirement set.
- DeepSeek обновлён на `deepseek-v4-flash` / `deepseek-v4-pro`; `reasoning_content` сохраняется между tool-call шагами.
- Backend проверяет выбранную модель по allowlist провайдера.

## RC2 — исправления после повторного runtime-review

В этой версии закрыты замечания независимой проверки, связанные прежде всего с безопасностью исполнения:

- backend больше не отменяет upstream-запрос на штатном `req.close`; отмена привязана к `req.aborted` и преждевременному закрытию ответа;
- внутренний `{id,name,arguments}` сериализуется в wire-формат Chat Completions `{id,type:"function",function:{...}}` только на границе API;
- `reasoning_content` отправляется только обратно в DeepSeek и только для DeepSeek-assistant ходов;
- tool call не выполняется без terminal `finish_reason`; незавершённый JSON аргументов блокирует исполнение;
- кнопка «Остановить» отменяет ожидание destructive-confirmation и после подтверждения сигнал проверяется повторно;
- если модель не указала `sheet`, имя активного листа фиксируется до подтверждения/исполнения;
- `delete_rows` больше не зависит от `getUsedRange`, поэтому корректно работает и на пустом листе;
- фильтры и структурные row-операции больше не создают ложный custom undo;
- undo записи/сортировки защищён от конфликта: если диапазон был изменён после действия агента, откат отказывается затирать свежие изменения;
- форматирование до 500 ячеек получает точный per-cell undo для bold/fill и точный numberFormat без восстановления значений/формул; большие диапазоны форматируются без обещания custom undo;
- Vite production build больше не запрашивает dev HTTPS certificate;
- локальный proxy по умолчанию привязан к `127.0.0.1` и имеет простой rate limit;
- добавлены unit-тесты сериализации tool-call history и provider-specific reasoning replay.

### Известные ограничения RC2

- структурные `insert_rows` / `delete_rows` намеренно не имеют custom undo: Office.js snapshot диапазона не восстанавливает все зависимые ссылки/объекты книги;
- `apply_filter` намеренно не занимает слот «Отменить»: восстановление предыдущего сложного состояния AutoFilter требует отдельного snapshot-механизма;
- production deployment должен находиться за реальной аутентификацией/reverse proxy; `PANE_TOKEN` — только дополнительная локальная защита;
- перед использованием на критичной книге нужен реальный E2E-тест в Excel Desktop/Online на копии файла.


## RC3 — reliability hardening

- Stop закрывает все незавершённые tool calls синтетическими `role: tool` cancellation results, поэтому история следующего запроса остаётся валидной.
- Лист без явного `sheet` фиксируется один раз в начале пользовательской задачи; переключение вкладки во время выполнения не меняет цель следующих команд.
- `insert_rows` и `delete_rows` инвалидируют custom undo stack: структурные сдвиги больше не оставляют устаревшие A1-адреса.
- UI показывает `undoable: false` / `undoNote` и название операции, которую реально отменит кнопка Undo.
- Вставка строк теперь требует подтверждения, поскольку безопасного custom undo для структурной операции нет.

## RC4: защита custom undo от ручных структурных изменений

- `WorksheetCollection.onChanged` отслеживает вставку/удаление строк, столбцов и ячеек (ExcelApi 1.9).
- При любом структурном сдвиге custom undo-стек очищается, даже если изменение выполнено вручную через UI Excel, а не агентом.
- Добавление/удаление листа также инвалидирует custom undo.
- Перед `delete_rows` интерфейс явно предупреждает, что собственного undo нет и предыдущая история отмены будет очищена.
- Добавлены root-тесты для structural-change policy, cancellation history и фиксации task sheet.

## RC5 safety fixes

- WorksheetCollection.onChanged requirement corrected to ExcelApi 1.9.
- Event handlers are async to satisfy current Office.js typings.
- Chart enum resolution is lazy, so agent tests can import modules without a browser Excel global.
- Custom undo now tracks a monotonic structural revision and aborts an in-flight undo if workbook structure changes while it is awaiting Excel.
- Added undo race tests; panel test script now includes workbook events, undo revision, and agent tests.


## RC6 monitor-gated custom undo

- Custom undo полностью отключён до успешной регистрации workbook structural-change monitor.
- Ошибка регистрации monitor очищает стек, инвалидирует выполняющийся undo и запрещает создавать новые undo-записи.
- `push()` возвращает `false`, когда защита недоступна; tool results в этом случае возвращают `undoable: false` и явный `undoNote`.
- Кнопка Undo в UI становится недоступной и показывает причину. При ошибке регистрации доступна команда повторного подключения защиты.
- После успешного повторного подключения начинается новая пустая undo-era: старые записи не восстанавливаются.
- Добавлены regression-тесты на блокировку создания/исполнения undo, восстановление после monitor reconnect и monitor failure во время in-flight undo.

## Этап 4 — поиск и локальное восстановление беседы

- `search_workbook` ищет значения и/или тексты формул на выбранных листах порциями, поддерживает регистр и полное совпадение, возвращает реально проверенные области и связанный с запросом `continuation`.
- `get_range_details` читает оформление, объединения, правила ввода и защиту области до 500 ячеек. Размер проверяется до загрузки подробных свойств.
- Поиск проверяет остановку и дедлайн между порциями по 5000 ячеек; один проход ограничен 100 листами и 200 совпадениями.
- Для сохранённых книг лента и контекст модели хранятся в локальном хранилище панели до 30 дней и в пределах 2 МиБ. Старые полные ходы вытесняются первыми.
- Истории разных URL книги не смешиваются. Несохранённая книга не получает автоматической привязки. После восстановления режим всегда сбрасывается в «Только анализ».
- Ответы инструментов сохраняются локально вместе с прочитанными данными ячеек — это нужно для целостности tool-call истории и явно указано в панели. Приватное reasoning провайдера не сохраняется.
- Оборванные пары вызов–ответ ремонтируются. Неизвестный результат записи получает `executionState=unknown` и не может считаться отменённым до выполнения.
- Чтения диапазонов, подробностей и результаты поиска получают `snapshot.id`. `recall_snapshot` возвращает снимок только как исторические данные со статусом `fresh`, `stale`, `evicted` или `missing`.
- Снимки ограничены 2 МиБ и 50 записями в памяти панели. Старые неиспользуемые снимки вытесняются; снимок активного плана записи удерживается до выполнения, отклонения или остановки.
- Версия книги независимо учитывает данные/формулы, структуру и оформление. Потеря event-monitoring или отсутствие нужного Office.js API консервативно делает снимок устаревшим.
