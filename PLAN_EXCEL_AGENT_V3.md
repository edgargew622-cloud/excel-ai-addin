# План улучшения Excel-агента — редакция 3

Дата: 14 сентября 2026 года.

Статус: предложение по реализации после изучения исходников и двух предыдущих планов. Пункты ниже описывают будущие изменения.

Предыдущие документы: [первый план](PLAN_EXCEL_AGENT.md), [редакция 2](PLAN_EXCEL_AGENT_V2.md).

## 1. Каким я вижу результат

Пользователь открывает Excel, запускает чат и может сказать: «Объясни эту книгу», «Найди исходные данные для этого показателя» или «Заполни разрешённые ячейки по этим условиям». Агент определяет контекст, читает нужные данные, объясняет выводы с адресами ячеек и показывает конкретные изменения до выполнения.

Для этого нужны четыре способности: ориентироваться в книге, сохранять существенные сведения во время задачи, управлять правками и проверять результат. Надёжный запуск обеспечивает доступность этих способностей каждый день.

Предлагаю выпускать изменения небольшими завершёнными релизами. После каждого — проверка на этом ПК и на тестовой книге. Сложность ниже относительная; календарные сроки уточняются после первых измерений.

| Релиз | Результат для пользователя | Сложность |
| --- | --- | --- |
| 0. Подготовка | Проверяемая исходная версия и понятная диагностика возможностей Excel | Небольшая |
| 1. Рабочий запуск | Надстройка доступна после входа в Windows и восстанавливается после сбоя | Средняя |
| 2. Ориентация в книге | Агент знает листы, выделение и основные объекты; доступен режим «Только анализ» | Средняя |
| 3. Исследование | Агент ищет данные, читает оформление и работает с длинным диалогом | Средняя–высокая |
| 4. Управляемые правки | Пользователь видит предпросмотр, подтверждает изменения и получает фактический результат | Высокая |
| 5. Проверка и восстановление | Агент находит ошибки и предлагает доступное восстановление с точным описанием его границ | Высокая |

Первый заметный результат — релизы 0–2. Учёт стоимости и сложное сжатие истории не должны задерживать появление списка листов и текущего выделения; простые ограничения объёма вводятся сразу.

## 2. Что уже есть и на что опираемся

По проверке исходников:

- Панель написана на React и TypeScript. Операции Office.js выполняются в панели; локальный сервер пересылает запросы провайдерам ИИ.
- Рабочий запуск использует Vite на порту 3000 и отдельный HTTPS API на порту 3001.
- Объявлены девять инструментов; единственный инструмент чтения содержимого — `get_range_values`.
- Активный лист фиксируется в начале задачи. Аргументы проверяются по JSON-схемам перед выполнением инструмента.
- Есть подтверждения, отмена ожидания ответа и частичный custom undo с контролем структурных изменений.
- История передаётся модели целиком. Один запрос чтения возвращает значения, формулы и числовые форматы; лимит — 20 000 ячеек.
- Существующие 11 автоматических тестов и проверка типов панели и сервера прошли при изучении проекта. Это исходная точка; сценарии в самом Excel проверяются отдельно.

Сохраняем ограничения объёма, проверку аргументов и защиту undo. Улучшения вносим последовательно, с возможностью вернуться к предыдущей рабочей сборке.

## 3. Релиз 0 — подготовка и быстрые исправления

1. Подготовить `.gitignore`, исключив ключи, зависимости, сборки, сертификаты и журналы; оставить пример конфигурации без секретов. Затем включить локальный контроль версий. Публикация репозитория для этого не нужна.
2. Объединить запуск тестов панели и сервера. Фактический исходник серверных тестов — `server/src/protocol.test.ts`.
3. Дополнить правила агента синтаксисом записи формул через `range.formulas`: английские имена функций и соответствующие разделители. Проверить применение формул в русскоязычном Excel.
4. Устранить рассогласование `PANE_TOKEN`: сейчас клиент содержит пустую константу, а сервер читает переменную окружения. Выбрать и проверить единый механизм локального доступа. Ключи провайдеров остаются только на сервере.
5. Явно определить путь загрузки `server/.env`, чтобы запуск из другой рабочей папки не менял конфигурацию.
6. Проверять при запуске наборы Excel API, которые действительно нужны функциям надстройки. Показывать доступные возможности и причины отсутствия отдельных функций.
7. Добавить измерение длительности запросов и размера результатов без записи содержимого ячеек в технические журналы.

**Критерий готовности:** есть воспроизводимая проверка проекта, известны возможности установленного Excel, настройки читаются одинаково при ручном и автоматическом запуске.

## 4. Релиз 1 — один рабочий сервер

Собранную панель и `/api` обслуживает один процесс Node.js. Основной адрес предлагаю сохранить: `https://localhost:3000`. Это уменьшит изменения в уже установленной надстройке. Vite остаётся для разработки.

Что сделать:

- Раздавать только каталог собранной панели `dist/`; исходники проекта, `.env` и сертификаты не должны попадать в статическую раздачу.
- Сохранить доступ через IPv4 и IPv6 localhost, ограничив сервер локальным компьютером. Проверить реальные адреса подключения.
- Сохранить доверенный HTTPS-сертификат и добавить диагностику его срока действия. Продление не должно требовать отключения проверки сертификатов в Windows.
- Настроить запуск при входе пользователя в Windows и восстановление процесса после аварии. Повторные попытки ограничить по частоте, размер журналов — ротацией.
- Проверять идентификатор и версию приложения через health endpoint: занятый порт может принадлежать другой программе. Чужой процесс автоматически не завершать.
- При переходе согласовать задачу автозапуска с существующим ярлыком, чтобы они не создавали дубликаты сервера.
- Предусмотреть локальную команду диагностики: процесс, порт, HTTPS, версия сборки, наличие конфигурации. В загруженной панели отдельно показывать состояние API и ошибки провайдера.
- Сохранить предыдущую рабочую сборку и понятный способ возврата после неудачного обновления.

Автозапуск сервера и автоматическое раскрытие панели в каждой книге — разные функции. Этот релиз обеспечивает готовность сервера; поведение открытия панели проверяется отдельно на существующей и новой книге.

**Критерий готовности:** после нового входа в Windows и повторного открытия Excel чат работает без терминала; остановка рабочего процесса приводит к его восстановлению; повторный запуск не создаёт второй экземпляр. Эти проверки выполняются на ПК, а не только HTTP-запросами.

## 5. Релиз 2 — карта книги и первый режим анализа

Добавить три инструмента:

| Инструмент | Содержание ответа |
| --- | --- |
| `get_active_context` | Контекст текущей книги в сессии, активный лист, активная ячейка и выделенные области, время получения сведений |
| `list_sheets` | Идентификаторы и названия листов, порядок, видимость, защита; ограничение выдачи и продолжение списка |
| `get_sheet_overview` | Границы данных и области с оформлением, таблицы, именованные диапазоны, краткий перечень диаграмм и сводных |

Обзор возвращает метаданные. Пустой лист, несколько выделенных областей и недоступное выделение обрабатываются явными состояниями. Отсутствие доступа нельзя выдавать за отсутствие данных.

На вопрос «что выделено» достаточно текущего контекста. На вопрос «как устроена книга» нужен список листов и выборочный обзор. Полный обход книги при каждом сообщении не требуется.

Одновременно:

- Ввести лимит байтов одного ответа и общего запроса к модели, сохранив лимит ячеек. При неполной выдаче возвращать признак неполноты и способ продолжения.
- Добавить режим «Только анализ». Изменяющие инструменты исключаются из списка модели и отклоняются при исполнении. Выбор режима виден пользователю.
- Связывать цели с идентификаторами листов в текущей книге. При переименовании или удалении листа обновлять контекст и отклонять устаревшую цель.
- Разделить текущее выделение и цель уже подготовленной операции: переключение листа не должно менять назначение правки.
- Начать модуль нормализации A1-адресов: проверка границ Excel, размеров, абсолютных ссылок и вложенности диапазонов. Именованные диапазоны разрешать через Excel с учётом области имени.

Полный столбец допустим в правиле доступа, например «можно менять H:H». Это не означает разрешение вычитать миллион ячеек. Чтения ограничиваются нужной областью; адрес записи нельзя молча сокращать.

**Критерий готовности:** агент правильно называет листы и выделение, различает пустой и недоступный лист, показывает таблицы. В режиме анализа попытка изменения отклоняется исполнителем.

## 6. Релиз 3 — поиск, содержимое и память задачи

### Адресное исследование

- Расширить `get_range_values` параметром состава ответа: значения, формулы, отображаемый текст, типы значений, числовые форматы. По умолчанию возвращать только нужный минимум; перед заменой формул обязательно читать формулы.
- Добавить `search_workbook`: явно выбранные листы или вся книга, тип поиска, лимит результатов и возможность продолжения. Различать поиск значений и поиск текста формул. Ответ должен сообщать, какие листы уже проверены.
- Добавить `get_range_details`: оформление, объединения, правила ввода, защита и условное форматирование — по запросу для ограниченной области. Базовую заливку не выдавать за окончательный вид ячейки при действующих условных форматах.
- Читать современные комментарии отдельно от старых примечаний; проверять поддержку каждого механизма.
- Для длительных операций показывать прогресс и проверять остановку между порциями данных.

Базовые комментарии доступны начиная с [ExcelApi 1.10](https://learn.microsoft.com/en-us/javascript/api/requirement-sets/excel/excel-api-1-10-requirement-set). Старые примечания представлены [Excel.Note в ExcelApi 1.18](https://learn.microsoft.com/en-us/javascript/api/excel/excel.note?view=excel-js-1.18). Первый план уже различал эти объекты. Неподдерживаемые примечания отмечаются как недоступные для чтения; обновление Office не является обязательным условием остальных улучшений.

### Память без потери оснований для ответа

Каждое чтение получает источник, адрес, время и идентификатор локального снимка. В рамках сессии сохраняются ограниченные снимки и важные факты, связанные с ними. Модель видит необходимые для текущей задачи данные; старые объёмные результаты можно заменить содержательной сводкой и ссылкой на снимок.

Фраза «прочитано A1:D50» годится для журнала, но не заменяет числа, которые нужны для расчёта. При сжатии необходимо сохранить существенные значения, выводы, незавершённые действия и решения пользователя. Связи вызовов инструментов и их ответов остаются корректными для протокола.

После изменения книги снимки помечаются как устаревшие. Перед записью нужный диапазон перечитывается. Старый снимок доступен как историческое состояние, с явной отметкой; его нельзя незаметно подменять текущими данными. Закрытие панели завершает такую память, пока отдельно не реализовано её сохранение.

Бюджеты учитывают весь запрос: системные правила, описания инструментов, историю и результаты, а также резерв для следующего ответа. Байты и токены считаются разными величинами. Ввести общий предел запросов, времени и вызовов инструментов; длинная серия чтений не должна обходить ограничения через несколько вызовов в одном ответе модели.

Учёт `usage` подключать для тех провайдеров, которые действительно его возвращают в используемом режиме. Если данных нет, показывать «нет данных» или явно обозначенную оценку. Денежную оценку выводить только с известным тарифом, валютой и датой его актуальности.

**Критерий готовности:** агент находит данные с адресами, продолжает длинный разговор без потери нужных чисел и сообщает о неполном поиске или устаревшем снимке. При исчерпании бюджета выдаёт выполненную часть и следующий шаг.

## 7. Релиз 4 — проверяемые изменения

### Правила книги

Пользователь задаёт допустимые для записи листы и диапазоны. Проверяются все цели операции, включая место назначения сводной, целые удаляемые строки и скрытые участки диапазона. Разрешение редактировать H:H не разрешает удалять строку целиком.

Правила хранятся с областью действия и привязкой к книге. Если привязку после повторного открытия нельзя подтвердить, прежнее разрешение автоматически не переносится. Защита листа и цвет оформления учитываются отдельно от разрешения пользователя.

Документация внутри книги помогает понять значения и методику. Уже заданные пользователем указания, например «заполни по правилам листа Инструкция», применяются в пределах задачи. Текст из ячеек не может расширять разрешения, отменять подтверждение или перенаправлять передачу данных. Новый существенный выбор уточняется один раз и сохраняется на время задачи.

### План правки

Предлагаемый контракт изменения содержит: идентификатор плана, книгу и листы, точные операции и адреса, исходные снимки, ожидаемый результат, возможность восстановления и состояние выполнения. План готовит исполнитель на основе фактических данных Excel и предложенных моделью операций.

Пользователь видит компактную таблицу «было → станет», количество затронутых ячеек и предупреждения о конкретных формулах или ограничениях. Большие изменения можно раскрыть. Подтверждение относится к этой версии плана; изменение целей или значений требует нового предпросмотра.

Первая версия групповых правок объединяет независимые операции в непересекающихся диапазонах. Структурные изменения и зависимые операции идут отдельными планами до появления проверенного механизма их исполнения.

### Выполнение и частичный результат

1. Проверить права, доступность листов, исходные значения, формулы и существенное оформление.
2. Перед каждой записью проверить актуальность цели и исходного состояния. Выполнять операции надстройки последовательно.
3. Явно различать запись литерального текста и формул; проверить строки, похожие на формулы.
4. Перечитать результат и вычисленные значения; учитывать режим расчёта Excel. Успешный вызов записи не означает, что формула рассчиталась правильно.
5. При конфликте, ошибке или остановке прекратить оставшиеся операции и показать: выполненные, невыполненные, неудачные и операции с неопределённым результатом.
6. Не повторять автоматически запись, результат которой неизвестен. Сначала прочитать книгу и установить её состояние.

Проверка снимка уменьшает риск конфликта, но не является блокировкой книги или атомарной транзакцией. Например, если из трёх операций две выполнены, отчёт должен прямо это показывать. Восстановление выполненной части предлагается только там, где сохранились достаточные снимки и текущие ячейки не содержат более свежих изменений.

**Критерий готовности:** нельзя выполнить изменённый после подтверждения план или записать вне разрешённых областей. Сбой на третьей операции оставляет точный отчёт о первых двух; остановка не выдаётся за автоматический откат.

## 8. Релиз 5 — диагностика и восстановление

Добавить `find_cell_errors` с ограничением области и выдачей адресов, формул и типов ошибок. Сравнивать ошибки до и после правки, чтобы отличать новые от существовавших. Подозрительные отличия формул обозначать как гипотезы для проверки, а не автоматически исправлять.

Оптимизировать снимки оформления с помощью пакетного чтения свойств ячеек. Замерить время, память, число обращений и точность восстановления. Затем при необходимости увеличить действующий лимит в 500 ячеек; общий предел размера снимков остаётся. Это соответствует подходу Microsoft: выбирать нужные свойства, объединять операции и ограничивать объём данных. [Рекомендации по производительности](https://learn.microsoft.com/en-us/office/dev/add-ins/excel/performance).

Копию листа можно использовать как дополнительную сохранённую версию его данных. Полный откат удаления строк требует более широкого решения: например, ссылка `=Данные!A5` на другом листе может превратиться в `#REF!` после удаления строки. Копия листа «Данные» сама по себе не восстанавливает эту формулу. [Microsoft о последствиях удаления ссылочных ячеек](https://support.microsoft.com/en-US/Excel/how-to-correct-a-ref-error).

Поэтому:

- Сначала проверить возможность создать полную копию текущей книги с несохранёнными изменениями и восстановить её в установленном Excel, сохранив формат файла и необходимые объекты.
- Пока этот путь не проверен, структурные операции явно отмечать как не имеющие полного автоматического отката.
- Для обычных правок развивать существующий custom undo: проверять исходные условия восстановления и исключать перезапись более свежих ручных изменений.
- В панели показывать доступные точки восстановления и их область действия. Срок хранения и очистка копий должны быть понятны пользователю.

**Критерий готовности:** диагностика указывает конкретные ячейки, а каждая предложенная отмена имеет проверенную область восстановления. Межлистовые ссылки и ручные изменения включены в проверку отката.

## 9. Проверки входят в каждый релиз

| Сценарий | Что проверяем |
| --- | --- |
| Новый вход в Windows, занятый порт, остановка сервера | Надёжность запуска, отсутствие дубликатов и понятную диагностику |
| Пустая книга, скрытые листы, несколько выделений | Точность контекста и различение пустоты и ошибки доступа |
| Две открытые книги, переименование листа | Изоляцию сессий, целей и разрешений |
| Русская локаль, формулы и строки со знаком равенства | Корректность записи и вычисленного результата |
| Длинные строки, большой лист, неполный поиск | Ограничение объёма, продолжение и честный отчёт |
| Оборванный поток, некорректный JSON, ошибка провайдера | Отсутствие исполнения незавершённых команд |
| Нет `[DONE]`, но есть корректное завершение шага | Совместимость согласно протоколу конкретного провайдера |
| Пользователь изменил ячейку во время предпросмотра | Остановку устаревшего плана |
| Ошибка посередине группы и повторное подключение | Отчёт о частичном результате и отсутствие повторной записи |
| Команда внутри ячейки, выход за разрешённый диапазон | Соблюдение полномочий, заданных пользователем |
| Удаление строки с зависимыми формулами на других листах | Реальные границы восстановления |

Парсер адресов, бюджетирование, переходы состояния плана и обработка потока проверяются автоматическими тестами. Совместимость Office.js, восстановление и запуск после перезагрузки проверяются в Excel. В результатах явно разделять «прошли тесты кода» и «проверено в Excel».

## 10. Предложения для дальнейших версий

- Кнопка «Что ты сейчас видишь»: показывает лист, выделение, уже прочитанные области и сведения, которые агент ещё не получал.
- Ссылки на ячейки в ответах: нажатие переводит к источнику вывода в этой книге.
- Карточка задачи: цель, исследованные области, предложенные и выполненные изменения, доступная отмена.
- Настройки правил книги с разрешёнными областями и пояснениями пользователя.
- Диагностика стоимости и качества на одинаковых задачах для выбранных пользователем моделей. Учёт стоимости сам по себе не должен менять выбранного провайдера.
- Проверка совместимости модели с инструментами перед включением её в рабочий список.

Подробные настройки диагностики размещать отдельно от основного чата. Пользователю постоянно нужны текущая книга, режим доступа, выбранная модель и состояние задачи.

На первую очередь не включать произвольное выполнение кода из ответа модели, универсальный анализ всех зависимостей Excel, работу с несколькими книгами одной правкой и управление интерфейсом по скриншотам. Каждая из этих возможностей требует отдельной проверки области действия и надёжности.
