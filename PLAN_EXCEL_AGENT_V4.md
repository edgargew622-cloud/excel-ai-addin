# План развития Excel-агента — редакция 4

Дата: 14 сентября 2026 года.

Статус: план следующих работ. Создание документа не означает, что перечисленные функции реализованы.

Основание: [V3](PLAN_EXCEL_AGENT_V3.md), [решения к V3](PLAN_V3_DECISIONS.md), проверка текущих исходников и восстановление запуска надстройки. Этот документ задаёт актуальный порядок реализации; предыдущие планы остаются историей обсуждения.

## 1. Какого результата добиваемся

Надстройка доступна после входа в Windows. Пользователь открывает книгу и просит объяснить её устройство, найти данные или заполнить конкретную область. Агент находит источники, показывает адреса, предлагает понятные изменения, выполняет их в заданных границах и проверяет результат.

Первая законченная версия должна проходить три сценария:

1. «Объясни эту книгу»: определены листы и таблицы, выводы подтверждены прочитанными ячейками.
2. «Заполни только H2:H100»: показано «было → станет», исполнитель не допускает записи вне разрешённой области.
3. Пользователь изменил ячейку во время подтверждения: устаревший план остановлен, предложен новый предпросмотр.

Архитектуру React + TypeScript + Office.js + локальный сервер сохраняем. Работу делим на небольшие проверяемые изменения.

## 2. Подтверждённое исходное состояние

- Панель и API запускаются отдельно: Vite на 3000, HTTPS API на 3001.
- Причинами недавней недоступности были остановленные серверы и отсутствующая регистрация доверенного каталога. Серверы запущены, каталог зарегистрирован.
- В Excel открыта тестовая книга: панель отрисовалась, кнопка «Отправить» доступна. Это проверка загрузки, а не качества выполнения задач моделью.
- Прошли 9 тестов панели/агента и 2 серверных теста, проверка типов и сборки панели и сервера.
- Есть девять инструментов, из которых содержимое читает только `get_range_values`. Есть проверка аргументов, подтверждения, остановка и ограниченный custom undo.
- В Git есть подготовленные изменения и удаления, включая модули бюджетов, истории и запуска. Они не считаются реализованными возможностями текущей версии. Перед следующими изменениями нужно разобраться с их назначением; автоматически восстанавливать или отменять их нельзя.

Проверка запуска после нового входа в Windows, полный цикл запроса к провайдеру и сценарии записи на реальных книгах ещё не подтверждены этой проверкой.

## 3. Очерёдность

| Этап | Результат | Зависимость |
| --- | --- | --- |
| 0. Исходная версия и критические статусы | Проверяемая база, отсутствие ложного сообщения «ничего не выполнено» | Нет |
| 1. Надёжный запуск | Рабочая панель доступна без терминала | Этап 0 |
| 2. Контекст и анализ | Агент ориентируется в книге, режим анализа технически запрещает изменения | Этап 0; выпуск после этапа 1 |
| 3. Одна проверяемая правка | Разрешённый диапазон, предпросмотр, проверка конфликта и результата | Этап 2 |
| 4. Поиск и длинные задачи | Адресный поиск, ограниченный контекст, восстановление беседы | Этапы 2–3 |
| 5. Групповые правки и восстановление | Управляемое выполнение нескольких операций и проверенные копии | Этапы 3–4 |

Первый целевой выпуск — этапы 0–3. Поиск, сложная память и групповые операции не должны задерживать его. Календарные сроки определяются после первого этапа и замеров в Excel; относительная сложность возрастает от небольших изменений этапа 0 до высокой на этапах 3–5.

## 4. Этап 0 — зафиксировать базу и устранить опасную неоднозначность

### Работы

1. Сопоставить рабочие файлы, индекс Git и последний коммит. Зафиксировать, что входит в исходную рабочую версию. Секреты, сертификаты, журналы и сборки исключить из контроля версий; сохранить пример конфигурации.
2. Добавить единую команду проверки: тесты панели, тесты сервера, проверка типов и сборка. Сохранить проверку манифеста отдельной явно вызываемой командой, если ей требуется сеть.
3. Ввести результат исполнения: `not_started`, `applied`, `verified`, `failed_before_write`, `unknown`. Если запись прошла, а чтение для проверки или undo упало, сообщать об уже выполненной записи и неполной проверке. При неизвестном результате запрещать автоматический повтор до перечитывания книги.
4. Валидировать аргументы до показа подтверждения. Ошибки подготовки цели также возвращать как результаты инструментов; не оставлять незакрытые пары вызов–ответ в истории.
5. Добавить бюджет задачи: число ответов модели, число читающих и изменяющих вызовов, общее время. Начальные ориентиры из V3 — 20 / 30 / 8 / 5 минут, с последующей калибровкой. Учитывать каждый вызов внутри массива `tool_calls`.
6. Установить пределы байтов результата и полного запроса уже здесь. Серверный предел тела запроса не заменяет управление контекстом. Не обрезать JSON посередине; возвращать явную неполноту и способ продолжения.
7. По истечении времени прекращать ожидание модели и новые операции. Уже отправленная в Excel запись может завершиться: учитывать её фактическое состояние. Ожидание пользовательского подтверждения учитывать отдельно от активного времени задачи.
8. Явно описать синтаксис формул в правилах агента. Отделить системные сообщения о лимитах от ответов модели.

### Проверка готовности

- Ошибка чтения после успешной записи не приводит к повторной записи.
- Остановка и ошибка подготовки не оставляют невалидную историю инструментов.
- Ограничения работают и для нескольких вызовов в одном ответе.
- Проверки выполняются одной командой и дают воспроизводимый результат.

Основные файлы: `src/agent/loop.ts`, `src/excel/excelTools.ts`, `src/excel/toolSchemas.ts`, `src/taskpane/api/client.ts`, `package.json`.

## 5. Этап 1 — запуск, который не нужно чинить вручную

### Работы

- Один рабочий HTTPS-процесс обслуживает `/api` и только собранную панель из `dist/` на `https://localhost:3000`. Vite остаётся для разработки на 3100 с отдельным манифестом и GUID.
- Путь к `server/.env` определяется относительно приложения, а не текущей папки запуска.
- Сохранить работу IPv4/IPv6 localhost. Проверять адрес подключения и допустимые Host/Origin; отклонять чужое происхождение до исполнения API. Отдельно проверить запросы Office без Origin и dev-прокси.
- Удаление `PANE_TOKEN` выполнять вместе с проверенной локальной границей доступа, а не отдельным промежуточным изменением. Ключи провайдеров остаются на сервере.
- Health endpoint возвращает идентификатор приложения и версию. При занятом порте не завершать чужой процесс.
- Ввести один механизм фонового запуска, защиту от дубликатов, восстановление после аварии и ротацию журналов. Согласовать его с существующим ярлыком автозагрузки.
- Добавить команду диагностики: процесс, порты, HTTPS и срок сертификата, версия, доступность каталога и совпадение манифеста. Не выводить ключи и содержимое книги.
- Сохранить предыдущую рабочую сборку и инструкцию возврата. Обновление не должно оставлять смесь старых и новых файлов.
- Панель показывает состояния подключения и кнопку повторной попытки при недоступном API.

### Проверка готовности

После нового входа в Windows надстройка открывается без терминала. Повторный запуск не создаёт дубликат. После аварийной остановки сервер восстанавливается. Рабочая и dev-панели доступны одновременно. Проверки выполняются на ПК, включая реальный Excel.

Основные файлы: `server/src/server.ts`, `server/package.json`, `vite.config.ts`, `manifest.xml`, отдельный dev-манифест, `scripts/`, `src/taskpane/Taskpane.tsx`.

## 6. Этап 2 — научить агента видеть книгу

### Инструменты

| Инструмент | Что возвращает |
| --- | --- |
| `get_active_context` | Идентичность книги в сессии, активный лист, ячейка, выделенные области и время чтения |
| `list_sheets` | ID, имена, порядок, видимость, защита листов; ограниченная выдача |
| `get_sheet_overview` | Границы данных, таблицы, имена, краткие сведения о диаграммах и сводных |

Обзор содержит метаданные, а не весь лист. Пустота, недоступность и неполнота — разные состояния. Полный обход книги при каждом сообщении не нужен.

### Работы

- Режим «Только анализ»: скрывает изменяющие инструменты от модели и запрещает их в исполнителе, включая фильтры и создание объектов.
- Диагностика возможностей Office.js управляет доступностью инструментов и проверяется повторно при исполнении.
- Привязка целей к ID листа и текущей книге. Удаление или неподтверждённая идентичность блокирует операцию; переименование не перенаправляет её на другой лист.
- Общий модуль A1: границы Excel, абсолютные ссылки, прямоугольники, вложенность и пересечение. Полные строки и столбцы допустимы в правилах доступа, но не дают права вычитать неограниченное число ячеек. Именованные диапазоны разрешаются через Excel с учётом области имени.
- Минимальный контекст автоматически добавляется к задаче. В панели видны книга, лист, режим и состояние работы.
- Расширить чтение выбором свойств: значения, формулы, текст, типы, числовые форматы. По умолчанию — минимум для задачи.

### Проверка готовности

Агент объясняет структуру тестовой книги и называет выделение без подсказки адресов. Проверены пустые и скрытые листы, несколько выделений, переименование и две открытые книги. Попытка записи в режиме анализа отклоняется исполнителем.

## 7. Этап 3 — одна правка от предпросмотра до проверки

Сначала реализовать полный путь для `set_range_values`. Затем подключать форматирование и остальные операции. Структурные операции до появления резервных копий сохраняют отдельное подтверждение с явной границей восстановления.

### Последовательность

1. Получить цель задачи и разрешённые пользователем листы/диапазоны.
2. Разрешить адреса и перечитать исходное содержимое.
3. Сформировать неизменяемую версию плана: книга, лист, адрес, исходное состояние, новые значения/формулы и доступность отмены.
4. Показать «было → станет», число ячеек, заменяемые формулы и ограничения восстановления.
5. После подтверждения проверить версию плана, права, идентичность цели и исходное состояние. При конфликте предложить новый предпросмотр.
6. Выполнить запись, перечитать результат и сравнить с ожидаемым. Учесть режим расчёта; не менять глобальные настройки расчёта молча.
7. Показать фактический результат, найденные ошибки, доступную отмену и область проверки.

### Правила

- Разрешение изменить H:H не позволяет удалить целую строку. Для сводной проверяется область назначения и возможное расширение; если границы нельзя установить, операция не входит в обычный разрешённый диапазонный план.
- Данные и инструкции из ячеек не могут расширять права или отменять подтверждение пользователя.
- Литеральный текст, похожий на формулу, и настоящая формула различаются явно; проверяется обратное чтение.
- Сравнение со снимком уменьшает риск конфликта, но не является блокировкой книги или атомарной транзакцией.
- Сканирование ошибок использует одну заранее зафиксированную область до и после записи. При ограниченном покрытии отчёт прямо называет границы.
- Все операции надстройки, включая undo, выполняются последовательно. Изменения пользователя в Excel остаются возможны и учитываются проверками.

### Проверка готовности

Проходят три целевых сценария из раздела 1, русские формулы и литеральные строки, конфликт после предпросмотра, остановка и ошибка после записи. Существующие ошибки формул не объявляются новыми. Отмена не затирает более свежие ручные изменения в проверяемой области.

## 8. Этап 4 — поиск, память и восстановление разговора

### Поиск и подробности

- `search_workbook`: поиск значений или текста формул, выбранные листы, лимит, продолжение, список реально проверенных областей.
- `get_range_details`: оформление, объединения, правила ввода и защита ограниченной области. Комментарии и старые примечания подключаются отдельно по доступности API.
- Длительное чтение делится на порции; между ними проверяются остановка, время и объём.

### Память

- Разделить видимую ленту, контекст модели и снимки книги.
- У снимка есть источник, адрес, время и версия. Размер хранилища ограничен байтами; вытесняются старые снимки, не нужные активному плану.
- Расширить события книги: обычные правки значений, структурные изменения и необходимые изменения оформления учитываются независимо от наличия undo. При неполном покрытии событий перед выводами и записью перечитывать необходимые данные.
- Старые снимки выдавать только как исторические. `recall_snapshot` сообщает об устаревании или вытеснении, не подменяя данные текущими.
- Сжатие не должно зависеть от угадывания «незакрытого обещания» в тексте модели. Исполнитель явно удерживает снимки плана; при нехватке бюджета для остальных данных предлагает дочитывание или остановку с отчётом.

### Сохранение беседы

- Сначала определить привязку: сохранённая книга, новая книга, копия, переименование и «Сохранить как». При сомнении не соединять беседы автоматически; разрешения на запись автоматически не восстанавливать.
- Хранить беседы локально вне файла книги, с удалением из панели, ограничением объёма и срока хранения. Не создавать две сменяющие друг друга системы хранения без практической необходимости.
- Ответы инструментов уже содержат данные ячеек. Формат сохранения должен явно решать, что исключается, что сохраняется и как это объясняется пользователю.
- При восстановлении ремонтировать пары вызов–ответ. Прерванная запись с неизвестным результатом не объявляется «отменённой до выполнения»: её состояние проверяется чтением. Автоматически повторять записи нельзя.
- После возврата к беседе считать сведения о книге устаревшими до проверки.

### Проверка готовности

Длинный разговор не теряет нужные основания для ответа, не превышает бюджет и корректно сообщает о неполном поиске. Две книги не смешивают беседы. После закрытия панели разговор восстанавливается без повторного исполнения операций.

## 9. Этап 5 — групповые операции и резервные копии

### Группы

- Начать с нескольких обычных записей в непересекающиеся диапазоны. Один план, одно подтверждение, отдельный статус каждой операции.
- Не переставлять смешанные чтения и записи автоматически: чтение после записи может проверять её результат. Неоднозначный ответ возвращать модели с просьбой разделить шаги.
- Непересечение адресов не доказывает отсутствие зависимостей. Поддерживаемые виды групп и порядок исполнения определить явно; пересечения и неподдерживаемые зависимости отклонять до записи.
- Вставка и удаление строк — отдельные планы. После ошибки останавливать оставшиеся операции и показывать выполненную, невыполненную и неопределённую части.
- Не обещать атомарность и общий откат там, где их нет. Восстановление выполненной части требует проверки актуального состояния.

### Копии

- Проверить выгрузку полной книги на установленном Excel: доступность, несохранённые изменения, время и размер, сохранность объектов.
- Сохранять исходный формат; не переименовывать любую книгу в `.xlsx`.
- Если резервное копирование требует предварительного сохранения исходной книги, включить это действие в явное подтверждение.
- Сервер принимает срезы в ограниченную временную загрузку с ID, проверяет порядок, полноту и размер, затем публикует готовую копию. Пути хранения задаёт сервер; незавершённые загрузки очищаются.
- Восстановление сначала ручное: открыть проверенную копию. Копия листа не считается полным восстановлением межлистовых ссылок.
- Ограничить объём и срок хранения. Прямые зависимые ячейки не считать полным графом влияния: цепочка зависимостей может продолжаться дальше.

### Проверка готовности

Сбой на третьей операции корректно отражает первые две. Повторное подключение не повторяет записи. После структурной правки резервная копия открывается с исходными межлистовыми формулами и необходимыми объектами.

## 10. Проверки и правила выпуска

Для каждого этапа сохранять отдельно результаты автоматических тестов и проверки в Excel.

| Проверка | Где выполнять |
| --- | --- |
| Бюджеты, A1, права, состояния плана, восстановление истории | Автоматические тесты |
| Оборванный SSE, некорректный JSON, ошибка провайдера | Тесты клиента и агентского цикла с имитацией потока |
| Запись прошла, проверка упала; остановка между операциями | Тесты исполнителя с контролируемыми сбоями |
| Локальный доступ, конфигурация, статическая раздача | Серверные интеграционные проверки |
